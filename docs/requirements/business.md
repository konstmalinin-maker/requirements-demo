# Бизнес-требования

Каждый ID постоянен и не переиспользуется. Версии имеют вид `FR-001@v1`; изменения проходят через PR.

## BR-001@v1: Автономность
**Приоритет:** Must have.  
**Источник / связь:** Спонсор.  
**Статус:** Реализовано; верификация — по связанным тестам и RTM.

Все операции работают без сети; данные остаются на локальном диске.

**Критерий приёмки:** Отключённый сетевой доступ не влияет на add/list/search/edit/delete.

**Проверка:** `tests/test_acceptance.py::test_br001_offline_cycle`.

## BR-002@v1: Простота использования
**Приоритет:** Must have.  
**Источник / связь:** Спонсор.  
**Статус:** Реализовано; верификация — по связанным тестам и RTM.

Базовый сценарий add/list/search доступен через встроенную русскоязычную справку и осваивается за пять минут.

**Критерий приёмки:** Индивидуальная демонстрация по --help укладывается в 300 с; оценка новым независимым пользователем вне индивидуальной работы.

**Проверка:** `tests/test_acceptance.py::test_br002_help_and_basic_scenario`.

## BR-003@v1: Расширяемость экспорта
**Приоритет:** Should have.  
**Источник / связь:** Архитектор.  
**Статус:** Реализовано; верификация — по связанным тестам и RTM.

Новый формат экспорта подключается через реестр обработчиков без изменения ядра хранилища.

**Критерий приёмки:** Внешний обработчик получает снимок заметок; JSON-экспорт и тестовый формат работают без правки NoteManager.

**Проверка:** `tests/test_acceptance.py::test_br003_export_plugin`.
