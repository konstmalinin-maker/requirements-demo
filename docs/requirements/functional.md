# Функциональные требования

Каждый ID постоянен и не переиспользуется. Версии имеют вид `FR-001@v1`; изменения проходят через PR.

## FR-001@v1: Создание заметки
**Приоритет:** Must have.  
**Источник / связь:** UR-001.  
**Статус:** Реализовано; верификация — по связанным тестам и RTM.

Команда `note add --title "..." --body "..."` создаёт заметку. Заголовок после trim: 1–100 символов, текст после trim: 1–10000 символов. ID — полный UUID4 в hex (32 символа), даты — UTC ISO 8601.

**Критерий приёмки:** Успех: «Заметка создана. ID: ...». Пустые и слишком длинные поля отклоняются без изменения файла.

**Проверка:** `tests/test_notes.py::test_fr001_ur001_add_persists`.

## FR-002@v1: Список заметок
**Приоритет:** Must have.  
**Источник / связь:** UR-002.  
**Статус:** Реализовано; верификация — по связанным тестам и RTM.

`note list` выводит все заметки в порядке создания: `ID | Заголовок | Дата создания`.

**Критерий приёмки:** Пустой список выводит «Заметок пока нет», данные повторно читаются из JSON.

**Проверка:** `tests/test_cli.py::test_fr002_list_cli`.

## FR-003@v2: Поиск заметок
**Приоритет:** Should have.  
**Источник / связь:** UR-003.  
**Статус:** Реализовано; верификация — по связанным тестам и RTM.

`note search --query "..."` ищет подстроку в заголовке и тексте через Unicode casefold после удаления пробелов по краям запроса.

**Критерий приёмки:** Найдены совпадения разного регистра и в тексте; пустой запрос возвращает пустую выборку.

**Проверка:** `tests/test_notes.py::test_fr003_ur003_search`.

## FR-004@v1: Редактирование
**Приоритет:** Should have.  
**Источник / связь:** UR-004.  
**Статус:** Реализовано; верификация — по связанным тестам и RTM.

`note edit ID [--title ...] [--body ...]` изменяет хотя бы одно поле. Лимиты совпадают с FR-001.

**Критерий приёмки:** Неверные данные, отсутствие полей и неизвестный ID не меняют хранилище; ID и created_at неизменны.

**Проверка:** `tests/test_notes.py::test_fr004_ur004_edit`.

## FR-005@v1: Удаление с подтверждением
**Приоритет:** Could have.  
**Источник / связь:** UR-005.  
**Статус:** Реализовано; верификация — по связанным тестам и RTM.

`note delete ID` запрашивает «Удалить заметку? [да/нет]:». Удаление происходит только после «да» или «yes»; EOF означает отказ.

**Критерий приёмки:** Никакого флага обхода подтверждения нет. При отмене файл не меняется.

**Проверка:** `tests/test_cli.py::test_fr005_ur005_delete_confirmation`.
